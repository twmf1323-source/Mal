# Mal · 韓語文法筆記本

韓語文法規則筆記本：查詢以 **API 文法盤點** 為主；**尚未收錄**的名稱可加入待辦。  
規則標題格式：**功能名稱（韓語）**（例如 `禮貌體（-아/어요）`）。  
**不做**動詞變化格子；不規則各自獨立成卡。  
查詢模式為 **API 文法**／**API 單字**／**手動**（全關仍可選字套用）。文法盤點採 **形態素切詞 → API 獨立盤點 → 本地卡對照**（對齊日語筆記本的學校文法管線，語素層列參考 [Mirinae Explorer](https://mirinae.io/)）：先用 **Kiwi** 把語節拆成詞幹／助詞／語尾（含받침裡的 `-ㄴ`），API 不讀本地卡名、只依原句與語素盤點；完成後前端才嚴格對照本地規則卡。選字建議仍可用 Kiwi；查詢不再做本地文法掃描。

## 功能

| 功能 | 說明 |
|------|------|
| API 查詢 | 已收錄：句中多彩標記＋規則卡；未收錄：下方列表 |
| 查詢歷史 | 最近查過的句子（本機）；可「再看一次」／刪除／清空 |
| 規則 CRUD | 新增／編輯／刪除；標題中文（韓語） |
| 已收錄比對 | 盤點結果與筆記本規則標題嚴格比對 |
| 缺失→待辦 | 單筆或全部加入待辦，之後建立規則 |
| AI 自動填寫 | 設定 API Key 後依規則名補齊說明 |
| 匯入／匯出 | JSON 備份（設定頁） |
| 形態素分析 | 背景預設開啟；設定頁可關。查詢先切語素、API 獨立盤點，再嚴格對照本地卡；結果有語節／語素／句層角色層列。選字套用會依語素置頂建議（如選 `예쁜` → 冠形詞形（-ㄴ/은）） |
| 規則種子 | 沒有內建規則卡。開啟、匯入、匯出都會去掉 id 為 `seed-` 開頭的預設卡；自己新增的規則留下 |

## 快速開始

### 本機靜態伺服器（建議）

雙擊 `index.html` 會被瀏覽器擋住讀取本機 WASM。離線請雙擊 **開啟筆記本.bat**，或：

```bash
cd "韓語文法筆記本"
npx --yes serve .
# 或
python -m http.server 8080
```

瀏覽器開啟顯示的網址。

### 部署到 Netlify

1. 將此資料夾連到 Netlify（或拖曳部署）
2. Publish directory 設為專案根目錄（已提供 `netlify.toml`）
3. 無需 build

## 規則卡片欄位

```text
id, title, category, explanation, structure,
created_at, updated_at
```

- **title**：`功能名稱（韓語標記）`
- **category**：語尾／助詞／不規則／時態／敬語／連接／句型／其他
- **structure**：可視化結構式，如 `詞幹＋지 않다`、`나＋는→난`、開／閉用 `／` 分列
- **explanation**：概念說明；**盡量不附例句**
- 無 `keywords`（本地掃描已取消）、無變化格子

## 查詢流程

### 查詢（API 文法／API 單字／手動）

1. 輸入單詞或整句（API 文法或單字需已設定 API Key；手動模式可直接選字套用）  
2. Kiwi 切語素後，程式替每個文法候選與未覆蓋的助詞／語尾建立穩定編號；API 不看本地卡名，逐項回覆確認／改判／否決
3. 第一輪若漏答或暫不確定，只補查未完成項目一次；盤點完成後才與筆記本嚴格比對 → **已收錄**／**尚未收錄**（未建立深紅色）
4. 缺失可「加入待辦」或「建立規則」  
5. 句下顯示語節／語素／句層角色（可摺疊）

## 資料存放

- 瀏覽器 **localStorage**（鍵名 `kgn_*`，與日語 `jgn_*` 分開）
- 不再內建規則種子。`data/seed-rules.json` 是空陣列；開啟時會刪掉已存的 `seed-` 規則，也不會從 GitHub Pages 補回
- 設定頁可匯出／匯入 JSON；「清除規則」只清規則與待辦，不會載入預設卡

## 設計原則

1. 查詢以 **API 盤點** 為準；筆記本用嚴格比對標「已收錄」
2. 不規則另立規則，不做類型格子
3. 規則名統一 **功能名稱（韓語）**；API 盤點回傳亦收成此格式再對卡
4. **一次一個主題**：API 只報句中實際表面形；開／閉音節同文法可同卡，結構式「開…／閉…」
5. 語尾／助詞消歧與著色交給 Kiwi＋KoParse（設定頁可關形態素）

## 形態素分析（Kiwi + KoParse）

- 授權：LGPL-2.1-or-later，本機執行、不需付費或 API Key
- 模型與 WASM 在 `vendor/kiwi/`、`vendor/kiwi-nlp/`（首次載入約十幾秒）
- 查詢管線：Kiwi 切語素 → 為候選與助詞／語尾建立 checklist → API 逐項確認／改判／否決 → 僅補查漏答 → 前端嚴格對照本地卡 → 著色只落在標記本身
- 每個確認項目保存穩定 `grammarKey`；API 明確否決的候選不會再被本地 fallback 補回，仍未確認的項目會在畫面標成「待確認」
- 層列（語節／語素／角色／句層）對齊 Mirinae：詞常由詞幹＋助詞或語尾組成；받침裡的語尾（예쁜 的 ㄴ）單獨一欄
- 關閉形態素或切詞失敗時，回退舊的整句 API 盤點
